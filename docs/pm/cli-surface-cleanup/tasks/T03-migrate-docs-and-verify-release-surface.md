# T03 — Migrate documentation and prove the release surface

## Context

The published README, tutorial, how-to guides, generated command reference,
and shell completions currently advertise the retired commands. The project
defines `scripts/verify.sh` as its single definition-of-done gate
([`docs/contributing/development.md`](../../../contributing/development.md)).
This task makes the supported migration explicit and proves the shipped
surface matches the grammar. See the [epic](../epic.md) and [plan](../plan.md).

## What to do

- Regenerate `docs/reference/commands.md` from the final CLI grammar.
- Replace `init` setup steps with automatic initialization through `add` or
  `install`; replace status examples with `list`; remove `source` and `unlink`
  examples rather than inventing replacement features.
- Add concise migration/release notes for automation users: `source list` may
  use `add <source> --list`; narrowing agents uses `install --agent` with the
  complete desired set; removing the last agent means `remove <skill>`.
- Run targeted retired-command-reference searches, documentation examples, and
  the full repository gate. Record the release-note destination or leave it as
  an explicit maintainer handoff if this repository has no changelog file.

## Acceptance criteria

- [ ] Generated `docs/reference/commands.md` lists none of `status`, `init`,
  `source`, or `unlink` as top-level commands.
- [ ] README, getting-started tutorial, and supported how-to guides contain no
  executable invocation of a retired command.
- [ ] Migration guidance documents the supported `add --list`, exact-agent
  `install --agent`, and `remove` paths without promising equivalent
  `source inspect` or `source check` behavior.
- [ ] A targeted supported-doc/completion search finds zero retired command
  references, excluding this epic's historical planning artifacts.
- [ ] `./scripts/verify.sh` exits 0.

## Out of scope

- Publishing a release, tagging, or changing version numbers.
- A broad documentation redesign unrelated to the removed commands.
- Altering the existing user-owned worktree changes outside this epic.

## Notes

- The command reference declares itself generated by `cmd/gen-reference`; do
  not hand-edit it.
- The release manager decides where the breaking-change note is published.
